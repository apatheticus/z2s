# Zero-to-Ship — visual design system

One frozen system; all project visuals derive from it. Facts come from the repo
(README, manifests, code), never invented. Frozen for this run.

## Provenance

Derived from: `docs/_build/shell.py` — both the published document set's `TOKENS`
block and the Clayscape art engine (`CLAY`, `GLOW`, `WARM`) that draws every figure
in that set.
Mapping:      product tokens mapped 1:1; the clay roles are lifted verbatim from
the art engine's own five-material table, so a README diagram and a diagram on the
published site are formed from the same clay.

Record the same source path and its hash as `design_source_path` /
`design_source_hash` in each visual's manifest, so a later run can tell that the
upstream identity moved without being forced to re-render.

## Story extraction

Audience:     someone deciding whether a spec-driven method is worth adopting
Value:        turns a specification into a plan and a plan into finished work, with a gate at every step
Proof:        the method's own specification set is generated by the method and passes its own gates
First action: `/plugin marketplace add apatheticus/z2s`
Theme:        a handmade miniature world — the method sculpted as something small enough to pick up

Two emissives and no more, which is the art engine's own rule: cool carries data,
warm carries habitation. Everything else in a figure is matte and reflective.

Diagram-grammar bindings for any visual carrying `data-diagram`: `paper` → sweep,
`surface` → stone, `ink` → clay-ink, `muted` → structure-shade, `rule` →
stone-shade, `accent` → terracotta, `link` → glow-body.

### Typography

| Role | Stack |
| --- | --- |
| display | `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` |
| body    | `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` |
| mono    | `ui-monospace, SFMono-Regular, Menlo, monospace` |

The published document set loads Instrument Sans and JetBrains Mono over the
network. A committed SVG may not reference anything remote, so visuals use system
stacks instead. This is a deliberate divergence from the site, not a drift.

### Shape language

Nothing has a crisp corner. Radius 28 on a node body, 32 on anything that reads as
a solid block, 24 is the floor. Forms are chunky and wider than they are tall.
Spacing unit 8; gaps between nodes are 32 or 48.

### Motif

Seven small clay tiles in a row, lit one at a time from left to right — the chain
of documents, each waiting on the one before it. It appears once per visual, inside
the cell that names the chain, never as background texture.

### Composition rules

One subject per board, sitting on its own ground with clear sweep around it.
Important content stays 40 units clear of the edges. A figure never fills the frame
corner to corner: the pale sweep is a feature, not leftover space.

### Motion rules

- Seamless ambient loops, 8–14s each; state at t=D equals state at t=0.
- Loop length declared once as `data-loop-s`; every duration divides it evenly.
- Ease character: `cubic-bezier(.34,1.56,.64,1)` for anything material, and a plain
  `linear` for a flow token travelling a fixed path.
- Two motion ideas per board at most. The world should read as inhabited, never busy.
- No strobing, no flicker, no idle bobbing.
- On a diagram, motion never moves geometry: no node drifts, no connector redraws.
  What may move is a dash marching along a fixed path and an ordered emphasis.
- Every animated visual carries a `@media (prefers-reduced-motion: reduce)` block
  that stops all motion and leaves a legible still.

### Style

| Field | Value |
| --- | --- |
| Slug | `claymorphism` |
| Source | alias — the repo's own Clayscape art engine resolves to the catalog's clay idiom |
| Primary axis | material |

- **Intent** — fat rounded volumes that look pressed out of clay, sitting on a pale
  studio sweep with a soft shadow underneath. Chosen because the published document
  set already draws every one of its figures this way, and a README that looked like
  a different product would be the drift.
- **Palette treatment** — bodies in `stone`, the one decisive piece in `terracotta`,
  slate reserved for connectors and rims. Three clay colours per board and no more.
  Type on clay is `clay-ink`, near-black, because pale clay cannot carry white text
  at the contrast floor.
- **Shape language** — radius 24 minimum, 28–32 in practice. Nothing sharp, nothing
  thin, no diamonds: a decision is a rounded block that asks a question.
- **Material / depth** — two chained `feDropShadow` primitives per filter. A wide
  ambient shadow tinted `stone-shade` and a tight contact shadow in `stone-edge`.
  Ambient alone floats; contact alone looks stuck. A neutral grey shadow reads as a
  cutout and is never used.
- **Type treatment** — system sans, `600`–`700`, generous size, sentence case. Node
  names at 20, metadata at 16, and nothing thin.
- **Motion character** — the material does not squash on a diagram, because a squash
  is a transform on a node and the geometry checks measure committed coordinates.
  What moves instead is light: a cool emissive dash travelling the handoff path, and
  an ordered emphasis raising each stage in turn.
- **SVG recipes** — one shared `clay` filter carrying the ambient-plus-contact pair;
  a clipped ellipse at `0.34` opacity for the highlight arc, positioned so only its
  lower curve shows; a radial `sweep` gradient behind everything.
- **Relaxations** — filter depth 1 → 2, which is the shadow pair and the whole reason
  the material reads as clay. Contrast is not relaxed.
- **Never** — a sharp corner, a diamond, a grey shadow, ambient without contact, a
  straight-edged highlight where an ellipse arc belongs, white type on pale clay, a
  fourth clay colour, or a bob on something that is not changing state.

**The hero is pinned to the previous style at the owner's instruction.**
`docs/assets/hero.svg` stays in `bento-grid` and is gated against that slug; it is
the one visual in this repo not formed from clay. Its manifest records
`"style": "bento-grid"` so the pin is visible rather than looking like drift.
